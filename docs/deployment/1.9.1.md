# AB-Shop v1.9.1 — Deployment Guide

## What changed

- Public business/legal content is now stored only in the `settings` database table.
- Removed `config/private_content.php` and its example file.
- Added `tools/build-deploy.ps1` to generate a clean production tree and ZIP.
- Deployment notes are kept under `docs/deployment/` instead of the project root.

## 1. Database migration

Before relying on the new code, run this migration once in production:

```text
database/migrations/013_v1.9.1_db_site_content.sql
```

The migration uses `INSERT IGNORE`, so if a setting already exists in production it is preserved. This is intentional: the admin/database is the source of truth.

## 2. Build the production package

From the project root in PowerShell:

```powershell
.\tools\build-deploy.ps1
```

The script creates:

- `deploy/` — clean production web-root snapshot (gitignored)
- `dist/AB-Socks-v1.9.1-deploy.zip` — upload this ZIP to the web root
- `dist/013_v1.9.1_db_site_content.sql` — keep/run separately; do not upload it into the public web root

`config/config.php`, `database/`, `docs/`, `.claude/`, `tools/`, Git metadata, and runtime uploads are intentionally excluded.

## 3. Hosting

1. Apply the migration in phpMyAdmin (SQL tab).
2. Upload/extract `AB-Socks-v1.9.1-deploy.zip` into the existing application web root.
3. Keep the existing production `config/config.php`; it is never part of the deployment ZIP.
4. Do not replace or delete existing runtime files under `uploads/`.
5. Open the admin settings page and verify the business/legal content and payment settings.

## 4. Verification

Check the storefront, login/phone verification, checkout, payment methods, and admin pages after deployment.

No production database, payment gateway, SMS, or browser integration test is performed by the local build script.
